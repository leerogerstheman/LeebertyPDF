## LeebertyPDF 1.0.1

修复 1.0.0 的一个启动问题：**每次打开都会弹出一个 cmd 窗口，关掉它阅读器也跟着退出**。

### 原因

1.0.0 为了绕开 `ProcessStartInfo.EnvironmentVariables` 的 `NO_PROXY` / `no_proxy`
崩溃（详见 1.0.0 说明），把启动改成走 `cmd.exe /c set "NAME=" & electron ...`。
它确实躲过了那个异常，但 cmd 是**控制台程序**，于是：

- 多出一个 **cmd 窗口**；
- Electron 成了 cmd 的子进程，**关掉那个窗口就把阅读器一起结束了**。

### 修法

启动器现在自己 P/Invoke `CreateProcessW`，不再经过任何中间进程：

- 自己构造环境块 —— `NAME=VALUE` 以 NUL 逐个结尾、整块再以 NUL 收尾，
  按大小写不敏感排序并按名去重（kernel32 查环境变量用二分查找，顺序必须对），
  并传 `CREATE_UNICODE_ENVIRONMENT`；
- 于是**完全不需要碰** `ProcessStartInfo.EnvironmentVariables`，
  那个 `ArgumentException` 的根源也就绕过去了；
- **没有任何控制台窗口**被创建（实测无新增 `cmd.exe` / `conhost.exe`）；
- 启动器建完进程、关掉两个句柄就退出，阅读器**完全独立**，
  没有任何进程能连带把它结束掉。

顺带修好了参数引号：按 `CommandLineToArgvW` 的规则处理反斜杠连段与引号
（`2N+1` 反斜杠、结尾连段加倍），所以 `C:\Users\Some Name\...` 这类路径、
以及文件名里带空格的文档都能正确传入。

### 实测

| 检查 | 结果 |
|---|---|
| 新增 `cmd.exe` / `conhost.exe` 进程 | **0 / 0** |
| 启动器退出后阅读器仍在 | 是（直接子进程，句柄已关） |
| 窗口标题 | `sample-small.pdf — LeebertyPDF` |
| 第二次双击（单实例） | 复用窗口并切到新文档的标签页 |
| 含空格的路径与文件名 | `a document with spaces.pdf` 正常打开 |
| 8 个被污染的环境变量同时存在 | 全部剥掉，应用仍以 GUI 正常启动 |
| PDF 引擎 / 功能体检 / 界面自测 / 空白页 / 橡皮擦重排 | 20/20 · 47/47 · PASS · PASS · 3/3 |
